Algorithms

How every number is produced

Six independent dynamic-programming variants. The recurrences and reconstruction run in Java.

RECURRENCES

The two optimization problems

Longest Common Subsequence
L[i][j] = 0                   if i = 0 or j = 0
L[i][j] = 1 + L[i-1][j-1]     when characters match
L[i][j] = max(up, left)       otherwise
Unit-cost Levenshtein distance
D[i][0] = i; D[0][j] = j
D[i][j] = diagonal            when characters match
D[i][j] = 1 + min(del,ins,sub) otherwise

METRICS AND LIMITS

Interpretation

LCS similarity

2 × LCS length / (m + n) × 100. Both empty: 100%; one empty: 0%.

Edit similarity

(1 − edit distance / max(m,n)) × 100. Both empty: 100%; one empty: 0%.

Ambiguous IUPAC symbols are compared literally; they are not treated as guaranteed biological matches.

A HANDS-ON GUIDE TO SEQUENCE COMPARISON

About the project

Turn two DNA strings into a transparent algorithm story. This lab compares sequences with Longest Common Subsequence and Levenshtein edit distance, then lets you inspect the dynamic-programming work behind each answer.

ATGC

START HERE · 6 STEPS

Your first comparison

Follow this path once, then experiment with your own sequences and algorithm variants.

  1. 01

    CHOOSE YOUR INPUT

    Start with two strands

    Open Input. Type or paste a DNA sequence into A and B, or select an example dataset to load a ready-made pair. FASTA upload is useful when your sequences are in a file; choose the records you want to compare after upload.

    Try ACGTACGTA and ACGTTCGTA first: one base differs.

    ⌁
  2. 02

    CHECK THE STRANDS

    Read the validation cues

    Whitespace is removed and letters are converted to uppercase. The accepted IUPAC DNA alphabet is A C G T R Y S W K M B D H V N. Each sequence can contain up to 2,000 bases. Unsupported symbols or overlong input must be corrected before comparison.

    The normalized preview shows exactly what the server will analyze.

    ⌕
  3. 03

    SET THE METHOD

    Pick implementations to compare

    Choose an LCS variant and an edit-distance variant independently: full-table tabulation, memoization, or rolling rows. They compute the same answer using different strategies. Keep trace events and DP tables enabled when you want to inspect the computation; detailed visualization is limited to 30 bases per strand.

    For a first run, leave both selectors on full-table DP to get the clearest walkthrough.

    ⌘
  4. 04

    RUN THE ANALYSIS

    Compare on the server

    Press Compare sequences. The Java backend validates and normalizes the pair, runs both algorithms, reconstructs an LCS and a minimum-edit script, and returns the measurements. The browser displays that response—it does not recalculate the result.

    If validation fails, the error appears beside the run button; your inputs stay in the Input tab.

    ↗
  5. 05

    FOLLOW THE EVIDENCE

    Inspect the journey and matrices

    Open Analysis journey to follow validation, algorithm choice, and trace playback. Use Play, Next, Previous, or Jump to end; switch between the LCS and edit-distance matrices. Click a computed cell to see its recurrence. The DP visualizer gives you a focused matrix view.

    Base cases seed the edges; each later cell follows its algorithm’s recurrence.

    ▦
  6. 06

    INTERPRET & EXPERIMENT

    Read results, then vary one thing

    Results shows the LCS length/string, edit distance, edit operations, and two application-defined similarity percentages. Visit Algorithms to study recurrences and complexity, or Benchmark lab to measure implementations on generated inputs. Change one setting at a time to understand its effect.

    These similarity values are educational metrics, not biological identity scores.

    ↗

COMPLETE WORKSPACE GUIDE

What each tab is for

Use the tabs as separate workspaces. Entering or editing a sequence in Input does not expose it in Results; Results, matrices, and the journey only change after you deliberately run a comparison.

01

Input

Start here for every new comparison. Paste sequences in the two text areas, choose a prepared example, or upload a FASTA file. Read the normalized preview below each input before running: spaces are removed, lowercase is converted to uppercase, and only IUPAC DNA symbols are accepted.

Use it when: you want to create, clear, replace, or validate a sequence pair.

02

Analysis journey

This is the evidence trail for the most recent successful request. It shows the normalized input, the two selected algorithm variants, the validation outcome, and the returned DP trace. Playback controls let you move cell-by-cell through the selected table without changing the original input fields.

Use it when: you need to explain how the answer was produced in a demo or viva.

03

Results

Read the final measurements here: LCS length and reconstructed subsequence, edit distance, similarities, matched positions, and the minimum-cost edit script. These values belong only to the last completed run, so a partially edited sequence in Input cannot overwrite them.

Use it when: you want a clean conclusion for the sequence pair you just analyzed.

04

DP visualizer

Use the focused matrix view to inspect the returned LCS or edit-distance table. Switch between the two matrices and select a computed cell to see its recurrence rule and explanation. Detailed events are available for inputs up to 30 bases per sequence; larger runs still return their final metrics.

Use it when: you are studying table filling, base cases, and recurrence decisions.

05

Benchmark lab

Choose a problem, algorithm variants, sequence length, repetition count, and seed. The server generates the same input for every selected variant and reports measured runtime. Memoization is intentionally unavailable beyond 500 bases to avoid unsafe recursion depth.

Use it when: you need timing data or want to compare time and space strategies fairly.

06

Algorithms

Review the LCS and Levenshtein recurrences, deterministic tie-breaking, and complexity of all six implementations. This tab is reference material: it does not run an analysis or alter your result state.

Use it when: you need the theory behind a metric, trace event, or implementation choice.

07

About

Return here for the quick-start walkthrough, project purpose, course details, and team information. The guide is deliberately separate from analysis data, so it remains useful before any sequence has been entered.

Use it when: you are orienting a new user or introducing the project.
